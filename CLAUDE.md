# CLAUDE.md — Highborn

Jeu de dynastie et de bataille pour iPhone, en PWA statique (GitHub Pages). Spécification complète : `docs/cahier-des-charges.md` (à relire avant tout jalon).

## Commandes

| Commande                                           | Rôle                                                                             |
| -------------------------------------------------- | -------------------------------------------------------------------------------- |
| `npm run dev`                                      | Serveur de dev (`http://localhost:5173/CK3/`, ajouter `-- --host` pour l'iPhone) |
| `npm test`                                         | Tests Vitest du moteur (`tests/`)                                                |
| `npm run typecheck`                                | TypeScript strict                                                                |
| `npm run lint` / `npm run format`                  | ESLint / Prettier                                                                |
| `npm run build`                                    | Build de production (`dist/`), `VITE_BASE` règle le chemin (défaut `/CK3/`)      |
| `npm run simulate`                                 | 10 000 batailles IA contre IA, vérifie les cibles 9.11                           |
| `npm run simulate-campaign -- --years 50 --seed 1` | Campagne sans joueur (ajouter `--passif` pour un joueur inactif)                 |
| `npm run generate-map -- --seed 1066`              | Régénère `src/data/map.json`                                                     |

Les scripts passent par `vite-node` (nécessaire pour `import.meta.glob` des événements).

## Architecture

- `src/engine/` : moteur **pur**, sans DOM ni React. Point d'entrée unique `applyAction(state, action)` (`actions.ts`) qui clone l'état, crée un `Rng` depuis `state.rng`, applique, réécrit la graine. Les sous-modules reçoivent un `Ctx { state, rng }` et modifient la copie.
- `src/engine/turn.ts` : `endSeason` → déplacements et batailles (`war/moveAndDetect`) → si bataille du joueur, `phase = 'bataille'` et pause → `continueSeason` (sièges, mercenaires, épidémies, vie, successions, succès) → `startSeason` (revenus, progression, bâtiments, conseil, complots, IA, vie de cour `court.ts`, événements).
- Progression : talents par personnage (`Character.perks`, perdus à la mort) et héritages par maison (`Dynasty.legacies`) ; leurs bonus sont lus via `perkBonus(state, c, clé)` (données dans `data/perks.ts`).
- Économie locale (`engine/economy/`) : `local.ts` (pur, lu par `realm` : multiplicateurs d'impôts, conscription, contentement, édits) et `index.ts` (saison, révoltes, actions, emprunts, IA). Revenus d'un comté = base × impôts × contentement × souverain (gestion, talents, édits).
- Cour (`engine/entourage/`) : `roster.ts` (pur, lu par `realm` : capacité, salaires des courtisans extérieurs du joueur) et `index.ts` (candidats, rallier, pupilles, débauchage, trésorier, impayés). `npm run simulate-economy` (options `--recrute`, `--manuel`) mesure les faillites ; au départ, `world.ts` retire les compagnies de trop pour garder un revenu net positif.
- Carte (`engine/mapgen.ts`) : 48 comtés, 12 duchés, 3 royaumes, 8 domaines de départ de tailles `REALM_SIZES` (le joueur reçoit un domaine de 5 à 7). Le monde (`engine/abroad.ts`, données `data/abroad.ts`) : faits de saison chez l'IA ; `worldNews(state, …)` (`context.ts`) alimente `state.worldNews` (guerres, paix, morts, successions, mariages, alliances, titres, révoltes), affiché dans Monde › Nouvelles (`ui/components/News.tsx`). Les guerres des voisins (`bordersPlayer`) vont aussi dans les avis.
- Capitale et population : `County.seatOf` (un siège par seigneur, `ensureCapitals` dans `realm`, à chaque saison et après succession ou conquête), `County.vitality` (population = `basePopulation × vitalité`, `economy/local.ts`). Bonus dans les multiplicateurs de `local.ts` (`isCapital`, `countySlots`, `countyDevMax`) et `fortLevel` ; occupation, capitulation (`capitalFallen`) et perte dans `war/index.ts` ; action `moveCapital`. Constantes `BALANCE.capital` et `BALANCE.population`.
- Couleurs de maison : une par maison, jamais deux fois la même (`Dynasty.color`, hex). `engine/heraldry.ts` prend d'abord la palette `data/heraldry.ts`, puis crée des teintes (`HOUSE_COLOR_RANGE`) les plus éloignées des maisons vivantes ; fond des portraits, champ du blason (`houseColor`, `common.tsx`) et couleurs des royaumes sur la carte (`realmColors`, `MapView.tsx`).
- Diplomatie : appel à l'aide (`callToArms` avec subside, alliés ou non) et traités de terres (`engine/diplomacy/trade.ts` : `countyValue`, `tradeAcceptance`, `balanceOffer`, `proposeTrade`, cessions proposées par l'IA via l'effet `cession`) ; constantes `BALANCE.trade` ; interface `ui/components/Diplomacy.tsx`.
- Couronnes (`engine/crowns.ts`, `BALANCE.crowns`) : unions personnelles (`state.unions`, créées dans `succession`, fusion `fuseCrowns`, éloignement `distantFactor` lu par `local.ts` et `opinionOf`), loi agnatique (`heirsOf`), droits par le sang (`Character.houseClaims`, `grantHouseClaims` à la naissance, `claimInfo`, casus belli `dynastique` avec `claimantId`, `resolveDynasticWar`), prétendants, clauses de mariage (`clauseFactors`, `applyClause`), protection, pactes (`state.familyPacts`, `state.successionPacts`, `pactHeir`). Interface `ui/components/Crowns.tsx`.
- Influence et succession (`engine/influence.ts`, `BALANCE.influence`) : `state.influence[souverain]` (points, candidat soutenu), `successionLine`, `kinLabel`, `acclaimedHeir` / `afterSuccession` (appelés dans `succession`), chancelier « influence », `influenceFactor` dans les acceptations. Fiche de royaume `ui/components/RealmSheet.tsx` (`store.realmSheet`).
- Négociation de paix (`engine/peace.ts`, `BALANCE.peace`) : `PeaceTerms` (camp vainqueur, comtés, or), `peaceTermsAcceptance` (barre : état de la guerre + valeur des comtés + or), `balanceTerms`, `termsForMode`, `aiTerms` (ce que réclame l'IA), action `negotiatePeace`, `endWar(…, terms)` ; l'IA propose au joueur par un événement `sys_paix_*` portant `EventInstance.peace`. Interface `ui/components/Peace.tsx` (Armée › Guerres › Négocier la paix, fenêtre d'événement).
- Gouvernements et lois (`data/governments.ts`, `engine/government.ts`, `engine/laws.ts`) : `Character.government` (tribu, féodalité, monarchie centralisée ; effets revenus, levées, opinion des vassaux, lois permises), réformes `REFORMS` ; cinq lois de succession, ordre des héritiers par loi dans `heirsOf` (`orderByLaw`, élection `electionResults`), `lawCheck` / `changeSuccessionLaw` (coût, délai `LAW_COOLDOWN`), `heirUnderLaw` (aperçu). Interface `ui/components/Laws.tsx`.
- Une bataille peut naître d'un événement (`war/eventBattle.ts`, `BattleState.event`) : `closeBattle` applique alors l'issue sans poursuivre la saison.
- `src/engine/battle/` : bataille autonome (utilisée par le jeu et le script de simulation). L'IA Difficile choisit ses ordres par anticipation d'un round contre l'ordre prévu de l'adversaire.
- `src/data/` : tout le contenu et **toutes les constantes** (`balance.ts`, `units.ts`, `terrain.ts`, `traits.ts`, `buildings.ts`, `names.ts`, `map.json`, `events/*.json`). Aucun nombre d'équilibrage en dur dans le moteur.
- `src/ui/` : React 18 + Zustand (`store.ts`). L'UI ne modifie jamais l'état : elle appelle `dispatch(action)`. Sauvegarde auto à chaque fin de saison et en arrière-plan.
- Navigation (`store.ts`, `TABS`) : cinq onglets, un par question du joueur. Règne (`screens/Reign.tsx` : résumé, journal, livre), Cour (`Court.tsx` : souverain, maison, conseil, courtisans), Royaume (`Realm.tsx` : carte, domaine, trésor, lois), Armée (`Army.tsx` : troupes, guerres), Monde (`World.tsx` : cours, complots, nouvelles). `goTo(onglet, sous-vue, ancre)` ouvre une sous-vue (lue par `useFocusView`) ; `inspect({ kind, id, tab })` ouvre une fiche sur un onglet interne (personnage : aperçu, talents, famille, terres ; comté : aperçu, économie, bâtiments, terrain). La liste « À faire » et les pastilles d'onglets viennent de `ui/attention.ts` (le rappel de fin de saison en garde les points `endSeason`). « Fin de saison » est la bande `.endbar` au-dessus des onglets. Une aide de carte passe par `CardTitle help=…` (repliée derrière ⓘ), un choix aux libellés longs par `ChoiceGrid`, des sous-onglets par `Segmented className="subnav"` (fixés au défilement). Bulle de premier passage par sous-vue : `data/screenTips.ts` (une entrée par sous-vue, vérifié par `tests/screenTips.test.ts`), `components/FirstVisit.tsx` (vues gardées dans `localStorage`).
- Bilan et suivi (`engine/digest.ts`, `BALANCE.digest`) : `takeSnapshot` au début de `endSeason` (`state.lastSnapshot`), `seasonDigest` (« Depuis la saison dernière », Règne › Résumé), personnages suivis (`state.followed`, action `toggleFollow`, `followedChanges`), courbe du trésor (`recordTreasury` en fin de `startSeason`, `state.treasuryHistory`, `components/TreasuryChart.tsx`). Recherche : `components/Search.tsx` (loupe de la barre du haut). Tri des partis à marier : `components/Marriage.tsx`.
- Mode Trône de fer (`state.scenario = 'westeros'`) : carte `engine/scenario/westerosMap.ts` (un Voronoï par terre découpé dans le contour de `data/westeros/geography.ts`, `splitClip` sépare les rives d'une baie), maisons et personnages `data/westeros/houses.ts` (20 jouables, bannerets `MINOR_HOUSES`, âges de la saison 1), construction `engine/scenario/westeros.ts` (`newWesterosGame`, titres à libellé `label`/`realmLabel`, emblèmes `Dynasty.sigil`), ouverture `data/westeros/opening.ts` (événements embarqués par maison), saison `engine/scenario/westerosSeason.ts` (soulèvements des grands seigneurs, couronnes régionales, `BALANCE.westeros`). Trait `voeux` : n'hérite pas, ne se marie pas. Cours des grands seigneurs : `greatCourts`, `hasCourt`, `domainCounties` (realm). Carte colorée par grand seigneur régional (`regionLord`, MapView). Le Mur (`engine/scenario/wall.ts`, `state.wall`, `BALANCE.wall`) : frères, vivres, menace des Autres, sauvageons, verredragon ; chute après `strainToFall` saisons au-dessus de la défense, Longue Nuit (`County.blighted`, `nextToFall`, batailles d'événement contre l'armée des morts), aube ; actions `wallAct`. Essos (`engine/scenario/essos.ts`, `state.essos`, `BALANCE.essos`) : étapes de Daenerys, événements, débarquement à Peyredragon et guerre pour Port-Réal ; actions `essosAct`. `ironThrone` (westerosSeason) : qui tient Port-Réal reçoit la couronne. Interface `components/WallEssos.tsx` (Monde › Le Mur, Essos). Ambiance : classe `scenario-westeros` sur la racine (`App.tsx`, `styles.css`), entrée `components/WesterosStart.tsx`.
- `src/save/` : IndexedDB (idb-keyval), 3 emplacements, export/import JSON, `migrations.ts` (incrémenter `SAVE_VERSION` dans `engine/state.ts` et ajouter une migration à chaque changement de format).

## Conventions

- Textes du jeu en français ; code, identifiants et commentaires techniques peuvent être en anglais.
- TypeScript strict, pas de `any`.
- Tout tirage aléatoire passe par `ctx.rng` (jamais `Math.random` dans le moteur, sauf la graine d'une nouvelle partie).
- Une nouvelle règle du moteur arrive avec son test Vitest, avant le branchement UI.
- Ajouter un événement : un objet dans `src/data/events/*.json` (format dans `src/engine/events/README.md`). Aucun code.
- Mobile d'abord : zones tactiles ≥ 44 px, texte ≥ 16 px, appui long pour les infobulles (`<Tip>`), zones sûres.
- Hauteur d'écran iPhone : lancée depuis l'écran d'accueil, `main.tsx` (`fitScreen`) pose `--app-h` = hauteur réelle de l'écran ; `body` (fixe) prend cette hauteur (sinon WebKit découpe l'app à la fenêtre annoncée, parfois plus courte de 62 pt), `#root` le remplit et son `transform` en fait le repère de tous les éléments `position: fixed`. Ne pas remettre `100dvh`/`100vh` ni `inset: 0` sur `body`, ni faire déborder un enfant de `#root`. Paramètres affiche écran / fenêtre / app pour le diagnostic.
- Fenêtres (`Sheet`) : toujours rendues par portail dans `#root`, au-dessus des barres ; ne pas les recréer en `position: fixed` à l'intérieur d'un écran défilant (WebKit les enferme sous la barre d'onglets).
- Écran de débogage : appui long sur « Highborn » dans la barre du haut.

## Méthode de travail (section 15 du cahier)

Un jalon à la fois, plan court validé avant de coder, une branche par jalon, commits petits et explicites ; la fusion dans `main` déploie. Demander avant de changer une règle du cahier, d'ajouter une dépendance lourde ou de changer d'architecture. Signaler tout déséquilibre de `npm run simulate` avec une proposition chiffrée.

## État d'équilibrage connu

`npm run simulate` : les 6 cibles sont tenues (vérifié aussi sur 40 000 batailles avec `-- --n 40000`) depuis l'ajout des tactiques, de l'élan et des duels : mono-type ≤ 60 %, colline ≈ +15, montagne ≈ +18, commandant ≈ +13. L'élan reste volontairement faible (`elan.attackPerLevel` 0,015) : plus fort, il avantage l'infanterie lourde seule. Le bruit statistique est d'environ ±2 pts sur 10 000 batailles.
